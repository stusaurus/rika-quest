# フリコ・クエスト 2.5D体験設計
状態: 設計案（ゲームへの実装・実機検証は未完了）

## 目標
児童が時計塔を探索し、道具に触れ、予想と実験を繰り返すうちに振り子の法則を発見する。固定気味のカメラと絵画的な背景を用いた2.5Dで、触れる手応えと場面の一体感を重視する。iPhone Safariで遊べる既存のRika Questと21ステージ・49問・セーブを維持する。

## 画面と美術
- 金と青を基調とした時計仕掛けのファンタジー。既存の赤いマントの主人公、相棒、時計塔の絵を基準にする。絵の変更や新規素材は参照を基に個別に検証し、キャラクターの顔・衣装を勝手に変えない。
- 背景は遠景・建築・床・前景に分ける。動かす量を控えめにし、建物や床に描き込まれた部品が不自然にずれないよう元絵を確認する。分離できない部分は一枚のまま使う。
- 遊べる床の範囲を画面内に定義し、奥では主人公が小さく、手前では大きくなる。足元と影は同じ地点に置く。見えない障害物で通路を塞がず、装置の見た目と接触地点を一致させる。
- 前後関係は足元の位置で決める。主人公が装置の手前や奥へ移動したときの重なり、柱の手前を通るときの隠れ方を確認する。必要な前景だけを別素材にする。
- 光、粒子、画面の揺れは目的を絞り、文章・振り子・操作対象を隠さない。常時動く演出は控えめにし、動きを減らす設定を尊重する。

## 主人公と操作
- 待機・歩行・停止・調べるの各状態を定義し、歩き出しと停止を滑らかにつなぐ。少なくとも左右・奥・手前の見え方を用意し、1枚絵を反転する場合の衣装の矛盾を確認する。素材が揃うまで擬似的な動きは暫定扱いとする。
- スマホは移動スティックと画面内の目的物タップを併用。タップで近づく場合は障害物に詰まらず、到着後に調べる動作へつなぐ。指で隠れない位置に必要な操作のみ置き、安全領域を守る。PCはキーボードとポインターに対応する。
- 調べられる物は近づくと小さく反応する。離れているときは「近づく」、到着後は「調べる」と案内し、同じ対象への操作が二重に走らないようにする。
- 接触は「近づく→立ち止まる→手を伸ばす→装置が反応→実験へ」の順。手と操作部の位置を同じ座標から計算し、画面サイズや主人公の向きが変わっても光だけが離れた場所に出ないようにする。

## 第1ステージの体験設計
1. 止まった時計塔に入り、短い会話で「時計を動かしたい」という目的を示す。
2. 3つの発見対象を探索する。各対象は名前、近づいた時の反応、調べた後の変化を持つ。探索を強制する箇所と任意の箇所は既存の条件に合わせる。
3. 操作台に近づき、触れる動作から振り子実験へ入る。世界を見失わないよう背景と色調をつなぐ。
4. 糸の長さを変え、まず結果を予想し、動く振り子と計測値を見て確かめる。重さ・振れ幅の扱いは対象年齢に合う説明と既存の理科モデルを照合する。
5. 実験の成功で装置が起動する。封印の扉が開くのは発見と扉の謎解きの条件を満たした時だけ。演出・メッセージ・保存状態を一致させる。
6. 探索へ戻ったときは復旧した状態が見える。次の目的を短く示し、再挑戦もできる。

## 第11ステージへの展開
共振の広間でも床座標・接触・アニメーションを共通化する。振り子は同じ周期と異なる周期の比較が見えるようにし、共振の模式表現と、装置が起動するファンタジー演出を区別する。4回成功後の歯車や光は、装置側の反応として順に見せる。

## 実装の順序
1. 第一ステージの既存状態遷移、描画順、入力、保存、理科計算を整理。機能単位でコードと素材を分け、現行ゲームを壊さず比較できる試作を作る。
2. 床座標、歩行範囲、接触点、奥行き順を共通化し、320px・390px・PCで位置を合わせる。
3. 主人公の方向別の待機・歩行・接触素材を基準画像に合わせて制作し、切り替えと影を調整する。素材の品質が足りなければ公開版を置き換えない。
4. 第1ステージを探索から実験・扉まで通しで完成させる。実際の小学生が迷う箇所を観察して手直しする。
5. 共振の広間へ共通部分を移し、効果を確認する。他の19ステージへの展開は一律に急がず、各単元の体験を設計する。

## 完了の判断
- 320px・390px・横長PCで、主人公・足元・装置が重ならず操作でき、文字や操作部が隠れない。
- 左右と前後の移動、壁・装置への接近、タップ移動中の中断、接触後の実験開始、探索への復帰を確認する。
- 実験の正誤と扉の解放条件、セーブ・再読み込み、音の初期設定、既存21ステージ・49問の整合性を確認する。
- 通常・動きを減らす設定、処理落ち時、通信失敗時を確認する。iPhone Safariの実機で発熱・描画・タッチ・長時間プレイを確認し、計測条件と結果を記録する。
- 目標の見た目は参考画像と実際のゲーム画面を比較する。静止画だけでなく、歩行・接触・実験の動画で違和感を評価する。商用品質到達は実装と試遊の検証後に判断する。
